## 코드 수정 사항

### 1. `-1`을 이용한 실패 표시를 `bool` 반환값으로 변경

#### 수정 전

```cpp
void finding(vector<int> &v)
{
    ...
    else
    {
        v.back() = -1;
        return;
    }
}
```

불가능한 수열을 발견하면 실제 수열의 마지막 값을 `-1`로 변경해 실패 여부를 표시했다.

호출한 함수에서는 다시 마지막 값을 확인해야 했다.

```cpp
finding(v);

if (v.size() == n && v.back() != -1)
{
    return;
}
```

#### 수정 후

```cpp
bool finding(vector<int> &v)
{
    ...
    else
    {
        return false;
    }
}
```

재귀 함수 자체가 성공 여부를 `true`, `false`로 반환하도록 변경했다.

```cpp
bool check = finding(v);

if (check)
{
    return true;
}
```

#### 수정 이유 및 최적화된 부분

기존에는 `v`가 실제 수열 저장과 탐색 성공/실패 표시라는 두 역할을 동시에 담당했다.

수정 후에는 수열은 `v`, 탐색 결과는 반환값이 담당하도록 역할을 분리했다.

따라서 `-1`이라는 특수값을 관리하거나 다시 확인할 필요가 없어졌고, 재귀의 성공과 실패 흐름도 명확해졌다.

### 2. `temp`를 이전 반복에서 수정하지 않고 현재 `i`로 직접 계산

#### 수정 전

```cpp
int temp = v.size() - 2;

for (int i = 1; i <= v.size() / 2; i++)
{
    ...
    if (flag)
    {
        flag = false;
        temp -= 2;
    }
}
```

`temp`를 처음 한 번 계산한 뒤 반복할 때마다 `2`씩 감소시키며 다음 비교 위치를 구했다.

#### 수정 후

```cpp
for (int i = 1; i <= v.size() / 2; i++)
{
    int temp = v.size() - i * 2;
    ...
}
```

현재 검사하는 부분 수열의 길이 `i`를 이용해 필요한 시작 위치를 바로 계산한다.

#### 수정 이유 및 최적화된 부분

기존 방식은 현재 `temp` 값이 이전 반복에서 제대로 수정되었다는 것에 의존했다.

수정 후에는 각 반복이 독립적으로 자신의 시작 위치를 계산하므로 별도의 `temp` 상태 관리가 필요하지 않다.

---

### 3. `flag`를 각 반복 내부에서 새로 생성

#### 수정 전

```cpp
bool flag = false;

for (int i = 1; i <= v.size() / 2; i++)
{
    ...
    if (flag)
    {
        flag = false;
        temp -= 2;
    }
}
```

다음 부분 수열을 검사하기 전에 `flag`를 다시 `false`로 직접 변경해야 했다.

#### 수정 후

```cpp
for (int i = 1; i <= v.size() / 2; i++)
{
    bool flag = false;
    ...
}
```

#### 수정 이유 및 최적화된 부분

`flag`는 현재 길이 `i`에 대한 비교에서만 필요한 값이므로 반복 내부에서 새로 생성하도록 변경했다.

이에 따라 다음 반복을 위해 `flag`를 직접 초기화하는 코드가 사라지고, 이전 반복의 상태가 다음 반복에 영향을 줄 가능성도 없어졌다.

### 4. 성공한 재귀 결과를 반환값으로 바로 전파

#### 수정 전

```cpp
v.push_back(i);
finding(v);

if (v.size() == n && v.back() != -1)
{
    return;
}

v.pop_back();
```

재귀가 끝난 뒤 `v.size()`와 `v.back()`을 다시 검사해서 정답을 찾았는지 판단했다.

#### 수정 후

```cpp
v.push_back(i);

bool check = finding(v);

if (check)
{
    return true;
}

v.pop_back();
```

#### 수정 이유 및 최적화된 부분

재귀 함수가 이미 탐색 성공 여부를 알고 있으므로 호출한 함수에서 수열의 상태를 다시 분석할 필요가 없다.

정답을 찾으면 `true`가 재귀 호출을 따라 위쪽으로 계속 전달되고, 실패한 경우에만 `pop_back()`하여 다음 경우를 탐색하는 구조가 되었다.

```text
수정 전:
숫자 추가
→ 재귀 탐색
→ 수열의 크기와 특수값 검사
→ 실패 시 원상복구

수정 후:
숫자 추가
→ 재귀 탐색
→ true면 즉시 종료
→ false면 원상복구
```

---

## 정리

이번 수정의 핵심은 시간복잡도를 크게 줄이는 최적화보다는 **백트래킹 과정에서 관리해야 하는 상태를 줄이는 것**에 있다.

기존에는 `temp`, `flag`, `-1` 등의 값을 직접 변경하고 복구하면서 재귀 상태를 관리했다.

수정 후에는 필요한 값을 각 반복에서 새로 계산하고, 탐색 성공 여부를 `bool` 반환값으로 전달하도록 변경했다.

특히 실제 수열인 `v`에 탐색 상태를 저장하지 않게 되면서 전체 재귀 흐름이 다음과 같이 단순해졌다.

```text
값 추가
→ 조건 검사 및 재귀 탐색
→ 성공하면 true 반환
→ 실패하면 pop_back()
→ 다음 값 탐색
```
