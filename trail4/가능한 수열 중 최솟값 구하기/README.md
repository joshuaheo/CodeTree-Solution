## 개선점 및 배운 점

### 1. 재귀에서 `pop_back()`의 위치 확인

특정 조건에서 재귀 함수 내부에서 `pop_back()`을 수행한 뒤 `return`하는 구조를 사용할 경우, 호출한 함수로 돌아온 뒤에도 다시 `pop_back()`이 실행되는지 반드시 확인해야 한다.

```cpp
v.push_back(i);
finding(v);
v.pop_back();
```

재귀 함수 내부와 호출한 함수 양쪽에서 같은 원소를 제거하면 의도보다 원소가 하나 더 삭제될 수 있다.

백트래킹에서는 가능하면 **값을 추가한 함수에서 원상복구까지 담당하는 구조**로 통일하면 상태 관리가 편하다.

---

### 2. 특수한 값을 넣어 성공/실패를 표시하지 않기

기존에는 불가능한 수열임을 표시하기 위해 마지막 값을 `-1`로 변경했다.

```cpp
v.back() = -1;
```

하지만 `v`는 실제 수열을 저장하는 벡터이므로, 성공/실패 여부까지 벡터의 값으로 표현하면 하나의 변수가 두 가지 역할을 하게 된다.

재귀 함수의 반환형을 `bool`로 변경해 탐색 성공 여부를 직접 반환하도록 가능하면 한다.

### 4. 임시 변수의 범위를 필요한 반복 내부로 제한

`flag`는 현재 길이의 두 부분 수열이 서로 다른지를 확인하기 위한 임시 변수이므로 반복문 내부에서 매번 새로 생성하도록 했다.

```cpp
for (int i = 1; i <= v.size() / 2; i++)
{
    bool flag = false;
    ...
}
```

필요한 범위 안에서 변수를 선언하면 직접 초기 상태로 복구할 필요가 줄어들고, 다른 반복의 값이 남는 실수를 방지할 수 있다.

---

### 5. `bool` 함수는 모든 실행 경로에서 값을 반환해야 함

4, 5, 6을 모두 선택해 탐색했지만 성공하지 못한 경우에도 함수가 끝까지 도달할 수 있으므로 마지막에 반환값이 필요하다.

```cpp
for (int i = 4; i <= 6; i++)
{
    ...
}

return false;
```

`bool`, `int` 등 반환값이 있는 함수에서는 모든 실행 경로에서 적절한 값을 반환하는지 확인해야 한다.
