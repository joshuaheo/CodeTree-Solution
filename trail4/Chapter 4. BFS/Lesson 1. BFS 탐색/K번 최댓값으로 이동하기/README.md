# BFS 구조 개선 정리

## 1. 기존 코드 구조

기존 코드는 **좋은 후보를 먼저 찾고, 해당 후보까지 BFS로 갈 수 있는지 확인하는 방식**이다.

```text
finding()
  ↓
masking()
현재 값 이상인 칸을 visit으로 막음
  ↓
현재값 - 1부터 값 내림차순 탐색
  ↓
행 → 열 순서로 후보 찾기
  ↓
후보 주변에 진입 가능한 칸이 있는지 사전 확인
  ↓
checking()
후보까지 BFS로 갈 수 있는지 확인
  ↓
성공하면 이동
  ↓
finding() 재귀
```

즉 BFS의 역할은 다음과 같다.

```text
"이 후보까지 갈 수 있는가?"
```

후보를 먼저 정한 뒤, 후보마다 BFS를 실행해 도달 가능 여부를 확인한다.

---

## 2. 기존 구조의 특징

현재 코드는 가장 큰 값부터 후보를 찾는다.

```cpp
for (int i = v[row][col] - 1; i > 0; i--)
{
    for (int j = 0; j < n; j++)
    {
        for (int k = 0; k < n; k++)
        {
            ...
        }
    }
}
```

따라서 가장 좋은 후보가 바로 도달 가능하면 빠르게 끝날 수 있다.

```text
최고 후보 발견
→ BFS
→ 도달 성공
→ 즉시 이동
```

하지만 높은 우선순위 후보들이 도달 불가능하다면 다음과 같이 BFS가 반복될 수 있다.

```text
후보 A → BFS 실패
후보 B → BFS 실패
후보 C → BFS 실패
후보 D → BFS 성공
```

이 경우 같은 영역을 여러 번 탐색할 수 있다.

---

## 3. 추천 구조

추천 구조는 반대로 **현재 위치에서 도달 가능한 모든 칸을 BFS 한 번으로 찾고, 그중 가장 좋은 칸을 선택하는 방식**이다.

```text
K번 반복
  ↓
현재 위치에서 BFS 시작
  ↓
현재 시작값보다 작은 칸만 이동
  ↓
도달 가능한 모든 칸 방문
  ↓
방문하면서 최적 후보 갱신
  ↓
BFS 종료
  ↓
최적 후보로 이동
```

이 구조에서 BFS의 역할은 다음과 같다.

```text
"현재 위치에서 어디까지 갈 수 있는가?"
```

BFS 한 번으로 도달 가능한 영역 전체를 확인하기 때문에 후보마다 BFS를 다시 실행할 필요가 없다.

---

## 4. 두 구조의 핵심 차이

### 기존 구조

```text
후보 선택
   ↓
BFS로 도달 가능 여부 확인
```

### 추천 구조

```text
BFS로 도달 가능한 후보 전체 확인
   ↓
그중 가장 좋은 후보 선택
```

즉,

```text
기존 구조 = 후보 중심 BFS
추천 구조 = 영역 중심 BFS
```

라고 볼 수 있다.

---

## 5. `masking()` 제거 가능

기존에는 현재 값 이상인 칸을 미리 막는다.

```cpp
if (v[i][j] >= v[r][c])
{
    visit[i][j] = 1;
}
```

그리고 BFS에서 다시 `visit`을 검사한다.

```cpp
if (visit[tempr][tempc] == 1)
{
    return;
}
```

추천 구조에서는 BFS에서 바로 현재 시작값과 비교하면 된다.

```cpp
if (v[nr][nc] >= startValue)
{
    continue;
}
```

따라서 다음 과정이 필요 없어질 수 있다.

```text
masking()
→ visit에 이동 불가능 칸 저장
→ BFS에서 visit 확인
```

---

## 6. `visit`과 `s`를 하나로 정리 가능

기존 코드에서는 두 배열의 역할이 나뉘어 있다.

```text
visit
= 현재 값 이상이라 이동할 수 없는 칸

s
= 이번 BFS에서 이미 방문한 칸
```

추천 구조에서는 `visited` 하나만 두고 이동 조건을 별도로 검사하면 된다.

```cpp
if (v[nr][nc] >= startValue)
{
    continue;
}

if (visited[nr][nc])
{
    continue;
}
```

즉,

```text
값 조건
+
방문 여부
```

를 BFS 내부에서 직접 판단하는 구조가 된다.

---

## 7. 후보 주변 사전검사 제거 가능

기존에는 후보를 찾은 뒤 BFS를 실행하기 전에 주변을 먼저 검사한다.

```cpp
for (int t = 0; t < 4; t++)
{
    if (...)
    {
        if (v[dr[t] + j][dc[t] + k] < v[row][col] ||
            (dr[t] + j == row && dc[t] + k == col))
        {
            flag = true;
            break;
        }
    }
}
```

그 뒤 다시 BFS로 실제 도달 여부를 확인한다.

```cpp
flag = checking(v, row, col, j, k, visit);
```

현재 구조는 다음과 같다.

```text
후보 주변을 보고 갈 가능성이 있는지 확인
              ↓
BFS로 실제 도달 가능한지 다시 확인
```

하지만 BFS 자체가 도달 가능 여부를 판단하므로 이 사전검사는 필요하지 않다.

추천 구조에서는 애초에 BFS로 방문한 칸만 후보가 된다.

---

## 8. 값 내림차순 탐색 제거 가능

기존에는 가장 큰 값을 먼저 찾기 위해 값을 직접 감소시킨다.

```cpp
for (int i = v[row][col] - 1; i > 0; i--)
```

그리고 격자 전체를 다시 확인한다.

```cpp
for (int j = 0; j < n; j++)
{
    for (int k = 0; k < n; k++)
    {
        if (v[j][k] == i)
        {
            ...
        }
    }
}
```

추천 구조에서는 BFS로 새로운 칸을 방문할 때마다 현재 최적 후보와 비교하면 된다.

```text
새로운 칸 발견
    ↓
현재 best보다 값이 큰가?
    ↓
크면 best 교체
```

값이 같다면 문제의 우선순위대로 비교한다.

```text
값이 같음
→ 행이 더 작은가?
→ 행도 같으면 열이 더 작은가?
```

따라서 다음과 같은 전체 탐색 구조가 필요 없어질 수 있다.

```text
값 반복
→ 전체 행 반복
→ 전체 열 반복
```

---

## 9. 후보별 `checking()` BFS 제거 가능

기존 구조에서는 후보 하나마다 BFS가 실행될 수 있다.

```text
9 후보 → BFS
9 후보 → BFS
8 후보 → BFS
7 후보 → BFS
...
```

높은 값의 후보들이 모두 도달 불가능하면 같은 영역을 반복해서 탐색할 수 있다.

추천 구조에서는 한 번의 이동마다

```text
현재 위치에서 BFS 1번
```

만 실행한다.

각 칸은 `visited`를 이용해 최대 한 번 방문하고, 방문하면서 가장 좋은 후보를 기록한다.

```text
BFS 시작
→ 도달 가능한 칸 A
→ 도달 가능한 칸 B
→ 도달 가능한 칸 C
→ ...
→ best 결정
```

---

## 10. `finding()` 재귀를 반복문으로 변경 가능

기존에는 이동할 때마다 재귀를 호출한다.

```cpp
f--;
finding(row, col, v, visit);
```

하지만 문제는 최대 K번 같은 동작을 반복하는 구조이므로 반복문으로 표현할 수 있다.

```cpp
for (int move = 0; move < f; move++)
{
    // BFS

    if (이동 가능한 칸이 없음)
    {
        break;
    }

    row = nextRow;
    col = nextCol;
}
```

이렇게 하면 `f`를 전역 상태로 직접 감소시키지 않아도 된다.

---

## 11. 전체 구조 비교

| 역할 | 기존 코드 | 추천 구조 |
| --- | --- | --- |
| 이동 불가능 칸 판단 | `masking()` | BFS에서 값 직접 비교 |
| 이동 불가능 표시 | `visit` | 필요 없음 |
| BFS 방문 표시 | `s` | `visited` 하나 |
| 높은 값 후보 찾기 | 값 내림차순 반복 | BFS 중 `best` 갱신 |
| 후보 위치 탐색 | 전체 행/열 탐색 | BFS로 방문한 칸만 확인 |
| 후보 사전검사 | 주변 4방향 확인 | 필요 없음 |
| 도달 가능 검사 | 후보마다 `checking()` | BFS 한 번 |
| K회 반복 | `finding()` 재귀 | 반복문 |

# 핵심 정리

기존 코드의 흐름은 다음과 같다.

```text
후보를 먼저 찾는다
→ 후보가 갈 만한 곳인지 사전 확인한다
→ BFS로 실제 도달 가능한지 확인한다
→ 성공하면 이동한다
```

추천 구조는 다음과 같다.

```text
현재 위치에서 BFS를 한 번 실행한다
→ 갈 수 있는 칸을 모두 확인한다
→ 그 과정에서 가장 좋은 후보를 기록한다
→ BFS 종료 후 그곳으로 이동한다
```

기존 방식은 가장 좋은 후보가 빠르게 도달 가능한 경우에는 BFS를 조기에 종료할 수 있다는 장점이 있다.

하지만 최악의 경우에는

```text
후보 A → BFS 실패
후보 B → BFS 실패
후보 C → BFS 실패
...
```

처럼 같은 영역을 여러 번 탐색할 수 있다.

추천 구조는 한 번의 이동마다 BFS를 한 번만 실행하고 각 칸을 최대 한 번씩 방문하므로 최악의 경우 성능이 더 안정적이다.

가장 중요한 차이는 다음과 같다.

```text
기존 방식
= 좋은 후보부터 찍고 갈 수 있는지 확인

추천 방식
= 갈 수 있는 곳을 한 번에 확인하고 그중 좋은 후보 선택
```

이번 문제처럼 **현재 위치에서 도달 가능한 모든 칸 중 가장 좋은 칸을 선택하는 문제**에서는 영역 전체를 한 번 탐색하는 BFS 구조가 문제 조건과 더 자연스럽게 맞는다.
